# اتصال اختیاری مدل و تلگرام

برای اجرای نسخهٔ محلی هیچ کلیدی لازم نیست. دستور `python3 server.py` حالت fixture را اجرا می‌کند. در این حالت استخراج و انتخاب متن با قواعد قطعی انجام می‌شود؛ شبیه‌ساز پیام‌رسان رابط کاربری، به تلگرام واقعی متصل نیست.

این راهنما آماده‌سازی اتصال است. وجود فایل آداپتور یا نام سرویس، مدرک اتصال زنده یا موفق بودن آزمون آن نیست.

## متغیرهای محیطی

`.env.example` فقط الگوست. برنامه `.env` را خودکار بارگذاری نمی‌کند؛ متغیرها را در همان محیطی تنظیم کنید که فرمان اجرا را می‌زنید.

| متغیر | کاربرد |
| --- | --- |
| `QUOTE_LLM_PROVIDER` | `fixture` برای حالت پیش‌فرض؛ `groq` برای درخواست به سرویس مدل |
| `QUOTE_LLM_MODEL` | پیش‌فرض `openai/gpt-oss-20b` |
| `GROQ_API_KEY` | کلید حساب خودتان برای حالت Groq |
| `QUOTE_ANNUAL_RATE` | نرخ اسمی سالانه به درصد؛ پیش‌فرض `23` |
| `QUOTE_CSV_PATH` | اختیاری؛ مسیر فایل قیمت جایگزین |
| `QUOTE_DB_PATH` | اختیاری؛ مسیر پایگاه دادهٔ سابقه و درخواست‌ها |
| `TELEGRAM_BOT_TOKEN` | توکن ربات آزمایشی خودتان |
| `TELEGRAM_ALLOWED_CHAT_IDS` | شناسه‌های عددی مثبت چت خصوصی مجاز، جداشده با ویرگول؛ wildcard ندارد |
| `TELEGRAM_STATE_DB` | اختیاری؛ مسیر دفتر پایدار تحویل پیام‌های تلگرام |

مسیرهای پیش‌فرض در پوشهٔ پروژه‌اند: منبع `data/prices.csv`، سابقهٔ workflow در `.runtime/workflow.sqlite3` و دفتر تحویل تلگرام در `.runtime/telegram.sqlite3`. فایل‌های زمان اجرا هنگام استفاده ساخته می‌شوند و جزو بستهٔ تحویل نیستند.

مقادیر محرمانه را وارد کد، فایل تحویلی، ویدیو یا مخزن نکنید. عبارت‌های داخل نمونه‌های زیر جایگزین‌اند و کلید واقعی نیستند.

## Groq

در Terminal روی Mac یا Linux:

```sh
export QUOTE_LLM_PROVIDER=groq
export QUOTE_LLM_MODEL=openai/gpt-oss-20b
export GROQ_API_KEY="REPLACE_WITH_YOUR_KEY"
python3 server.py
```

در PowerShell روی Windows:

```powershell
$env:QUOTE_LLM_PROVIDER = "groq"
$env:QUOTE_LLM_MODEL = "openai/gpt-oss-20b"
$env:GROQ_API_KEY = "REPLACE_WITH_YOUR_KEY"
py -3 server.py
```

طبق [مستندات رسمی Groq](https://console.groq.com/docs/structured-outputs)، مدل پیش‌فرض از Structured Outputs با حالت strict پشتیبانی می‌کند. آداپتور دادهٔ استخراج‌شده را دوباره اعتبارسنجی می‌کند؛ درست بودن شکل JSON به‌تنهایی درستی معنای جواب را ثابت نمی‌کند.

در مرحلهٔ استخراج، متن درخواست، نام مدل‌های مجاز و زمینهٔ محدود به مدل می‌رسند. قیمت، درصد پیش‌پرداخت و تعداد اقساط به مدل داده نمی‌شوند. مرحلهٔ متن‌پردازی فقط وضعیت درخواست را می‌گیرد و شناسهٔ عبارت آغاز و پایان را از فهرست مجاز انتخاب می‌کند. متن مالی با کد ساخته می‌شود.

بعد از اجرا، حالت و trace همان درخواست را بررسی کنید. برچسب «حالت Groq» انتخاب ارائه‌دهنده را نشان می‌دهد؛ موفقیت تماس را باید در مراحل اجرای همان درخواست دید. مثلاً اگر فایل CSV نامعتبر باشد، درخواست می‌تواند پیش از تماس با مدل متوقف شود. خطای سرویس یا پاسخ نامعتبر می‌تواند مسیر را به fallback قطعی ببرد؛ این حالت باید به‌عنوان fallback باقی بماند و اتصال زندهٔ موفق گزارش نشود. شرایط دسترسی و مصرف سرویس به حساب ارائه‌دهنده بستگی دارد.

برای برگشت به اجرای بدون مدل ابری:

```sh
export QUOTE_LLM_PROVIDER=fixture
python3 server.py
```

## تلگرام آزمایشی

آداپتور از long polling استفاده می‌کند و به تونل عمومی HTTPS نیاز ندارد. از رباتی استفاده کنید که برای همین آزمایش در نظر گرفته شده است. نمونهٔ تنظیم در Mac یا Linux:

```sh
export TELEGRAM_BOT_TOKEN="REPLACE_WITH_YOUR_BOT_TOKEN"
export TELEGRAM_ALLOWED_CHAT_IDS="123456789"
python3 telegram_bot.py
```

عدد بالا صرفاً نمونه است؛ شناسهٔ واقعی چت خصوصی مجاز خودتان را قرار دهید. چند شناسه به صورت `123456789,987654321` نوشته می‌شوند. در Windows همین متغیرها را با قالب `$env:NAME = "VALUE"` تنظیم و `py -3 telegram_bot.py` را اجرا کنید.

سرور وب لازم نیست برای اجرای مستقل آداپتور تلگرام باز باشد؛ هر دو از همان موتور Workflow استفاده می‌کنند. نوع مدل نیز مستقل از کانال پیام است: ربات می‌تواند تلگرام واقعی را با پردازش fixture اجرا کند.

رفتارهای آداپتور:

- فقط چت خصوصی و شناسه‌های مجاز پذیرفته می‌شوند؛ `/start` پشتیبانی می‌شود.
- پیام غیرمتنی، توضیح مناسب دربارهٔ ورودی قابل پشتیبانی می‌گیرد.
- پیش از polling، وضعیت webhook بررسی می‌شود. اگر webhook فعالی وجود داشته باشد، برنامه متوقف می‌شود و آن را خودکار حذف نمی‌کند. این محدودیت با [Bot API تلگرام](https://core.telegram.org/bots/api#getupdates) هم‌خوان است.
- شناسهٔ update و وضعیت تحویل ثبت می‌شوند. timeout مبهم ارسال، مجوز ارسال دوبارهٔ خودکار نیست؛ وضعیت برای بررسی می‌ماند تا پاسخ تکراری فرستاده نشود.
- متن با `sendMessage` و بدون قالب HTML یا Markdown فرستاده می‌شود.

برای بررسی خواندنیِ وضعیت‌های نیازمند بازبینی، بدون ارسال دوباره:

```sh
python3 telegram_bot.py --review
```

این فرمان حداکثر ۱۰۰ رکورد نیازمند بررسی را از دفتر محلی می‌خواند و به تلگرام وصل نمی‌شود. وضعیت `needs_review` یعنی نتیجهٔ ارسال قطعی نیست؛ `failed` یعنی API درخواست را صریحاً رد کرده است. هیچ‌کدام خودکار دوباره ارسال نمی‌شوند.

## چک‌لیست تأیید اتصال

- [ ] نام حالت fixture، live یا fallback با اتفاق واقعی یکسان است.
- [ ] درخواست مشخص `۲۰۷ مدل ۱۴۰۲` عددهای همان ردیف CSV را برمی‌گرداند.
- [ ] درخواست بدون سال، سؤال تکمیلی می‌گیرد.
- [ ] در حالت زنده، انجام تماس موفق با سرویس واقعاً مشاهده شده است؛ صرف تنظیم کلید کافی نیست.
- [ ] در تلگرام، یک پیام از چت مجاز دریافت و پاسخ واقعی همان پیام مشاهده شده است.
- [ ] وضعیت webhook قبلی حفظ شده و پاسخ تکراری ارسال نشده است.
- [ ] نبود داده دربارهٔ نو بودن و موجودی در پاسخ پنهان نشده است.
- [ ] کلیدها، توکن‌ها و پایگاه دادهٔ زمان اجرا از بستهٔ تحویل کنار گذاشته شده‌اند.
